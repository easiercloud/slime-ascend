## Megatron `0002` 是否可删除

`patches/third_party/megatron/0002-Ascend-fix-attn-mask-type-checkpoint-save.patch` 暂时保留，原因有两项：

1. 兼容提交 MegatronAdaptor `f707a3b6...` 尚不包含异步 checkpoint `preload_tensors` 的同步 D2H 修复；该修复只出现在更新且 MCore 基线不同的 MA 历史中。
2. TENPU `2b8529f94...` 尚不包含后续的 `padding_causal` NPU FlashAttention 支持提交，因此当前组合仍需要 Megatron 侧的 mask 兼容。

这两个改动都是 Megatron 上层规避。最终应分别下沉到 MA checkpoint 适配层和 TENPU attention 层；待兼容基线同时包含两项下层修复后再删除 `0002`。

## Memory saver 审视

- `0001-fix-torch-memory-saver-allocation-lifecycle.patch` 为下层根因修复：显式保存 `is_paused`，避免重复 pause/resume、已经 unmap 后再次 free，并在 resume 后更新物理内存 handle。
- `0002-fix-tms-sglang-cuda-graph-api-and-preload-mode.patch` 为下层接口/启动契约修复：透传 `auto_dispatch_capture`，并对子进程同时设置 `TMS_HOOK_MODE=preload` 与 `LD_PRELOAD`。
- Slime 的 DeepEP 构造 wrapper 仍是上层规避，不应与上述下层生命周期修复混称为根因解决。需验证 DeepEP persistent buffer、动态 TMS region 与 graph capture 的组合后，再决定是否可移除 wrapper。

## `upstream-fixes` 完整性审计

对旧 dev 中五个补丁逐一与 v0.3.2 比对：

| dev 补丁 | v0.3.2 处理 | 原因 |
|---|---|---|
| `cp_utils.patch` | 不迁移 | `log_prob is None` 时补零会污染训练数据，是上层掩盖错误的规避，不是根因修复 |
| `megatron_bridge_utils.patch` | 不适用 | v0.3.2 已移除旧 `megatron_to_hf_mode == "bridge"` 路径和对应工具文件；不是“功能被上游等价吸收” |
| `megatron_utils_init.patch` | 不适用 | 依赖已删除的旧 AutoBridge 初始化路径；不是“功能被上游等价吸收” |
| `model_provider.patch` | 不适用 | 依赖已删除的 bridge mode / `patch_auto_bridge_hf_config` 结构；不是“功能被上游等价吸收” |
| `qwen3_5.patch` | 已恢复 | v0.3.2 未吸收。补回 Qwen3.5/VL vision tower、GDN linear-attention、MoE expert 等 Megatron-to-HF 映射 |

THD packed CP/TP 补丁仍单独保留；它处理 sequence metadata、镜像 CP 分片和 TP physical tail 一致性，属于数据/并行路径的根因修复，不使用补零掩盖错误。

## 补丁生成和回放约束

- 所有已登记 `.patch` 均为 `git format-patch` 邮件格式。
- Slime submodule 固定在官方 `3778dbf6...`；补丁按 `MANIFEST.toml` 顺序由 `build.sh` 使用 `git am` 应用。
- 第三方补丁由 `quick_install.sh`/Dockerfile 使用 `git am` 应用。
- 依赖契约（SGLang、router、MA、TENPU、Megatron）直接维护在外层 quick_install/Docker 配置，不再伪装成 Slime 上游 patch。
- `MANIFEST.toml` 记录稳定 ID、问题号、base commit 和文件 SHA256。

- The existing Qwen2.5-0.5B colocate Nightly short case now accepts `SLIME_TEST_REF_LOAD`, since the CI default checkpoint path was absent. Its first attempt stalled while the old TorchMemorySaver preload hook sent a 32-byte allocation to `aclrtMallocPhysical`: `/tmp/slime-latest-qwen05-nightly-short-sglang0521-npu8-11-20261026.log`. Diagnostic wheel returned CANN `507899` for size 32; the installed header labels it `ACL_ERROR_RT_DRV_INTERNAL_ERROR`. The [Ascend physical memory API](https://www.hiascend.com/doc_center/source/en/canncommercial/800/apiref/appdevgapi/aclcppdevg_03_0112.html) requires granularity-aligned sizes. The patch queries the actual CANN minimum granularity and forwards unaligned allocations to the ordinary ACL allocator.
- The second Nightly attempt passed NPU graph capture but exposed a Megatron initialization assertion in `torch_memory_saver/entrypoint.py`: the trainer starts with `TMS_INIT_ENABLE=1`, then Megatron opens a nested region for parameter buffers. The new patch saves and restores the prior region tag, active state and CPU-backup flag, so the inner region can be used without losing outer state. Logs: `/tmp/slime-latest-qwen05-nightly-tms-granularity-npu8-11-20261026.log` (failure) and `/tmp/slime-latest-qwen05-nightly-tms-nested-npu8-11-20261026.log` (success).
- New patch `patches/third_party/sgl-kernel-npu/0003-fix-tms-unaligned-allocations-and-nested-regions.patch` was replayed after the other two kernel patches on the exact installer baseline `9765e27532b8f854717eba1d3fb9a0bb97a0c887`. A wheel built from that exact replay was installed in the isolated container. Final Nightly Ray job `raysubmit_9x9u1asq1pbFkUNJ` succeeded with train step 0 and weight version update: `/tmp/slime-latest-qwen05-nightly-pinned-tms-npu8-11-20261026.log`.
